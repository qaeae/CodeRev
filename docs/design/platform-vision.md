# 平台愿景：从「审代码」到「管交付」

> 这是产品的终局形态。当前做的 B（变更追溯）和 A（PR 审查）只是它的第 1–3 环。

---

## 1. 完整链路

| 阶段 | 输入 | 产出 | 谁做 | 现在有没有 |
|---|---|---|---|---|
| **0 需求结构化** | PRD / 需求单 | `REQ-ID` + 可验收标准（AC）+ 依赖 + 风险 | 产品/BA，AI 辅助 | ❌ |
| **1 按标准拆分** | 结构化需求 + 架构约束 | 切片图（slice）+ **先冻结的契约** | 技术负责人拍契约，AI 给切法 | ❌ |
| **2 逐片实现** | 单个切片 + 契约 | 代码 + 单测 + PR | 开发，AI 审查/补测 | 🟡 A 轨道在做 |
| **3 拼装** | 各切片分支 | 合并后的需求分支 | 开发/集成负责人 | ❌ |
| **4 需求级验收** | 完整需求 + AC | 验收用例 + 执行结果 | AI 生成，人确认 | ❌ |
| **5 业务流联调** | 多需求 + 测试环境 | 跑通/失败清单 + 根因 | 全员，**最痛** | ❌ |
| **6 拍板** | 问题清单 + 证据 | 上线/延期/带病上线决策 | 1–2 个决策人，AI 出材料 | 🟡 B 轨道的定级是雏形 |

---

## 2. 三个真正的难点（不是模型能力问题）

### 难点一：「按需求审查」的前提是追溯，不是更聪明的模型

模型再强，如果没有 `需求 → 切片 → PR → 测试 → 验收证据` 的映射，它只能按通用规则审，审不出"这个实现偏了需求"。**地基不是 prompt，是追溯图谱。**

### 难点二：拼装阶段 80% 的问题出在契约，不是代码质量

两个切片各自都"审过了"，拼起来还是炸——字段可选性不一致、错误码各写各的、同一个折扣逻辑两处实现。这类问题任何单 PR 审查都发现不了，只能靠**契约注册表 + 契约测试**。

### 难点三：联调失败定位需要运行时数据

"50 个用例挂了"最费时的不是修，是**归类**：哪些是一个根因、哪些是环境问题、哪些是真 bug。AI 在这里价值最大（聚类 + 用 trace 把失败映射回切片），但前提是能拿到 trace。

---

## 3. 五条设计判断

1. **第一步不是拆，是"把散文变成断言"**。PRD 是散文，验收标准是可执行断言。没有 AC，拆分标准和审查标准都无从谈起。
2. **拆分标准应该是"契约稳定 + 依赖单向"**，不是按人头分。按人拆是最常见的做法，也最容易在拼装时爆炸。
3. **拼装环节要做"语义级冲突检测"**：两个切片是否重复实现同一业务规则、同一实体是否两套校验。比 diff 冲突检测难，但正是痛点。
4. **拍板支持的产品形态是"一页纸决策包"**：阻塞项 / 可带病上线 / 可延后，每条带证据、影响面、负责人、回滚方案，最后生成可签字的决策记录。
5. **买家变了**：从 Tech Lead（研发工具预算）变成交付负责人/项目经理（交付预算）。客单价更高，决策链更长。

## 4. 可行性分级（别一次全做）

| 阶段 | 现在能做到什么程度 | 卡点 |
|---|---|---|
| 0 需求结构化 | 70–80%，PRD 越规范越高 | 客户 PRD 质量参差 |
| 1 拆分 + 契约建议 | 60%，能给切法和耦合体检 | 契约要人拍板 |
| 2 切片审查/单测 | 80%（A 轨道的能力） | 已有方案 |
| 3 拼装/契约一致性 | 70%，OpenAPI diff 成熟 | 需要契约注册表 |
| 4 需求级验收 | 50% | AC→用例质量、环境 |
| 5 业务流联调 | 30–40%（定位强、造环境弱） | 测试环境、数据、trace |
| 6 拍板支持 | 80%（信息整合） | 组织信任 |

**结论：0/3/6 能立刻做差异化；5 最痛但最难单独交付。**

---

## 5. 与当前产品的关系

```
B（变更追溯）  → 链路第 1–2 环的数据底座：需求变更有记录、影响模块有标注
A（PR 审查）   → 链路第 3 环：切片级审查
V2（影响引擎） → 链路第 3–5 环：变更传播、契约一致性、联调定位
```

B 现在用 Excel 手工跑，正是为了**在没有系统的情况下先攒出图谱的边**。等这些边足够多，第 3–5 环才有训练和验证的素材。

---

## 6. 明确不做

- 不做 IDE 插件（不与 Copilot / Cursor 正面竞争）。
- 不做需求管理工具（不替代 Jira / 飞书）。
- 不做代码托管平台，只做"审查层"。
- 不做自动改代码并直接合并（V2 只做"生成测试 PR"且人工确认）。
